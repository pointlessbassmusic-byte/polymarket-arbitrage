## What it says (core ideas)

The video's frame, from its title, description and chapters: retail traders should use Claude Code the way a quant would, by implementing a technique that top hedge funds use (a Hidden Markov Model for market regimes), building and checking the core logic first, having Claude Code write the implementation, and then using the regime output to adjust an existing trading model. [meta]

1. **"Copying top hedge funds and quants" means HMMs, and the hedge fund is Renaissance.** [meta, bg, mine] The description promises to copy top quants; the first substantive chapter is "Hidden Markov Models." The canonical story behind that pairing: Jim Simons' first recruit at Monemetrics was Leonard Baum, co-inventor of the Baum–Welch algorithm for fitting HMMs, and Medallion is described as "a form of Leonard Baum's mathematical models expanded by algebraist James Ax"; the firm's current leaders, Peter Brown and Robert Mercer, came from IBM speech recognition, the field where HMMs were dominant. Whether the creator names Renaissance is unconfirmed; the association is the genre's standard pitch (the contemporaneous Lewis Jackson / Roan videos call the same thing "the Markov hedge fund method").

2. **What an HMM is, as the genre teaches it.** [bg] A hidden state `s_t ∈ {1..K}` follows a Markov chain with transition matrix `A` (`A[i,j] = P(s_{t+1}=j | s_t=i)`, rows sum to 1); the observed daily return `r_t` is drawn from a state-specific distribution, usually `r_t | s_t=k ~ N(μ_k, σ_k²)`. Parameters `θ = (π, A, μ, σ)` are estimated by Baum–Welch, which is "a special case of the expectation–maximization algorithm" that "makes use of the forward-backward algorithm to compute the statistics for the expectation step." Expected regime duration is `1 / (1 − A[k,k])`. The regime is then read off by decoding: Viterbi ("finds the most likely sequence of states, given all emissions") or posterior decoding ("also known as smoothing or forward-backward").

3. **HMMs identify regimes; they do not predict price.** [snippet] The indexed summary of this video describes HMMs as tools for identifying market regimes rather than predicting price. This is the correct and modest claim: the model estimates which of a few return-distribution states the market is in, and how sticky each state is.

4. **States have no built-in meaning; labels are assigned afterwards.** [bg] "Labels such as bull or bear are assigned afterward by inspecting the fitted parameters." In code this is `argsort(μ_k)` → Bear, Sideways, Bull, or a split by `σ_k` into low- and high-volatility. Two or three states "cover most chart uses."

5. **Build the core logic first; layer strategies second.** [snippet] The summary's "Building Core HMM Logic" section says the first step is building the core logic that determines the market regime, that this confirms the basic HMM model works before other strategies are layered on, and that this step could be skipped and done entirely in Claude Code. The chapter order (Hidden Markov Models → Building Core Logic → Using Claude Code → Adjusting Trading Model) is the same message: understand the component, verify it stands alone, then let the agent write it, then integrate.

6. **"Adjusting Trading Model" means regime-conditioning an existing strategy, not trading the regime.** [meta, genre, mine] The last chapter is about adjusting a trading model, which implies an existing strategy whose behaviour changes with the detected regime: trade only in favourable states, size by state, or switch sub-strategies by state (the QuantInsti template trains one classifier per regime and lets the HMM's one-day-ahead regime forecast choose which to use). The alternative genre design trades the regime directly: `signal = P(next=Bull | current) − P(next=Bear | current)`, position `= sign(signal)`.

7. **The simplest version of the method is a counted transition matrix, not an HMM.** [genre] In the Roan / Lewis Jackson framework that circulated in 2026 alongside this video: label each day from the trailing 20-day return with a symmetric threshold (±2% in the published skill, ±5% in the video description), count day-to-day label transitions into a 3×3 matrix and row-normalise, compute the stationary distribution as the eigenvector for eigenvalue 1, forecast `n` days ahead with `A^n` (Chapman–Kolmogorov), and note that multi-day forecasts collapse to the stationary distribution. The HMM "removes the subjective regime labels" and is offered as an optional layer: `GaussianHMM(n_components=3, covariance_type="diag", n_iter=200, random_state=42)` fit on one-dimensional daily returns, decoded with `predict` (Viterbi), states sorted by mean return. The published skill's HMM output is printed only; it does not feed the backtest.

8. **The genre's backtest, where it has one.** [genre] Expanding-window walk-forward: at each day `t`, fit the transition matrix on all labels before `t` (minimum 252 days), take the position at the close of `t`, score it on `t+1`'s return; Sharpe = `mean/std × √252` with no risk-free rate; max drawdown from the compounded equity curve; "trade count" is the number of daily positions, not round trips; no transaction costs, no separate out-of-sample period. The code claims "No lookahead. No tuning." This is true of the matrix and signal and false of the label threshold and window, which were chosen by someone looking at the data.

9. **A critique video exists for the genre.** [genre] "I Built the Viral Claude Code Trading Strategy Properly — Watch What Happens" (pythonforfinance.info) rebuilds an HMM regime strategy with a train/test split, feature scaling fit on train only, real Binance transaction costs, 2.5× leverage, grid search on the training set only, and "no parameter tuning on test data," saying this is "where most implementations get it wrong." Its chapter list is a usable checklist: constants and data; train/test split and feature engineering; scaler and HMM training; labelling bull and bear states; indicator confirmation counts; backtest function; grid search; apply to test; results. No numbers are public.

10. **The look-ahead mechanism specific to HMMs (the part the genre mostly gets wrong).** [bg] Filtered probabilities `P(s_t | r_1..r_t)` "use only data up to the current bar and are safe to act on live." Smoothed probabilities `P(s_t | r_1..r_T)` and the Viterbi path condition on the whole sample, so "historical labels look cleaner than live output," and a "prescient-looking regime plot" is the signature of smoothed output. In `hmmlearn`, both `predict` (Viterbi) and `predict_proba` (forward-backward posteriors) are computed "given all emissions"; the library exposes no filtered-probability method. A backtest that calls either on the full return series and then trades the resulting labels has used the future at every bar.

11. **Refitting is a second, independent look-ahead channel.** [bg] "Refitting parameters on new data shifts old labels even under filtered decoding." A regime series that is recomputed from scratch each day is not the series anyone traded; the fix is to freeze or version each fit and store the labels as they were emitted.

12. **Baum–Welch finds local optima; the state count cannot be chosen by likelihood.** [bg] The algorithm "finds a local maximum" and "does not guarantee a global maximum"; serious fits use several random restarts and keep the best likelihood, and a fit that "changes character on each re-run suggests the states are not well separated." Every added state raises in-sample likelihood, so `K` is chosen by BIC and by stability across refits, not by fit.

13. **Features and sample.** [bg] Fit on returns, not prices, so the series is roughly stationary; optionally add realised-volatility or range features, standardised; the sample must span several real regime changes (years of daily data).

14. **Regimes lag and do not time bars.** [bg] "Fitted probabilities lag genuinely new behaviour, and the model quantifies switching hazard rather than timing a specific bar"; "fitted regimes are not guaranteed to persist out of sample." The honest output of an HMM is a probability of being in each state and a hazard of leaving it.

15. **Claude Code's role in the video is implementer.** [meta, snippet, mine] The human supplies the concept (chapter 2), checks the core logic (chapter 3), has Claude Code write it (chapter 4), and integrates it (chapter 5). The "Using Claude Code" chapter occupies 12:00–19:45, which is the longest segment: the implementation, not the mathematics, is where the creator spends his time. His sibling video (resource 12) puts the same thing as "deterministic systems coded by Claude."

16. **Disclaimers and funnel.** [meta] Not a financial advisor; results not guaranteed; educational only. The description links the $149/month community and a 1:1 program. The word "profitable" in the description is not backed by any number recoverable from the video's public surface.

## What Mandel adopts

1. **Regime is a first-class latent variable in the substrate.** Because mispricings, spreads, fill rates and news flow on Polymarket and Kalshi cluster in time, and a strategy's edge measured without conditioning on regime is an average over states it may never trade in again. Mandel's regime engine is a component, with its own tests, evaluated before anything consumes it (resource 13's "core logic first").
2. **Filtered-only rule for every model-derived feature.** Because `predict`/`predict_proba` on a full series is look-ahead by construction. Any feature produced by a fitted model must be computed from data with `available_at ≤ decision_ts`; smoothed posteriors and Viterbi paths are permitted for diagnostics only and are tagged `diagnostic`, which the gate refuses as backtest input. This is MANDEL.md principle 9 (point-in-time) made specific.
3. **Freeze and version every fit; store emitted labels, not recomputed ones.** Because refitting shifts old labels even with filtered decoding. A fit is `{fit_id, train_window, θ, random_states, bic, code_hash}`; the regime series Mandel backtests on is the concatenation of what each frozen fit emitted at the time.
4. **Pre-register the refit cadence and the state count, and account for both as trials.** Because the number of states, the label threshold, the lookback and the refit schedule are all dials, and every dial multiplies the trial count that `deflated_sharpe_ratio` must be fed.
5. **Multiple restarts and a stability metric.** Because Baum–Welch finds local optima; Mandel fits with ≥ 5 seeds, keeps the best likelihood, and records `label_stability` (fraction of historical argmax labels unchanged after a refit). A model with low stability is not well separated and cannot feed a decision.
6. **Simplest baseline first.** Because the genre's own simplest version (a counted 3×3 transition matrix) is a legitimate baseline for the HMM; Mandel promotes a regime model only if it beats both the no-regime strategy and the counted-matrix baseline out of sample.
7. **Regime-conditioned reporting.** Because a strategy that works in one regime is a different object from one that works in all; `compare_strategies` output is extended with per-regime edge and per-regime Brier, and a strategy whose edge lives in one state gets a regime gate rather than a promotion.
8. **Regimes are hazards, not timers.** Because the HMM quantifies the probability of being in a state and of leaving it, and lags true changes; Mandel uses regime posteriors to scale exposure and thresholds, never as an entry signal on its own. Expected duration `1/(1−A[k,k])` must exceed the strategy's holding period plus the refit cadence, or the regime is not actionable after costs.
9. **"Named-institution technique" is a claim-import class.** Because "hedge funds use this" is the most common way a method enters a retail workflow; Mandel records it as `{claim, institution, technique, claimed_metric}` with no insight weight until the technique has a measured out-of-sample result on Mandel's own data.
10. **Model as implementer, human and tests as specifiers.** Because the video's working pattern, and resource 12's, is that Claude writes the code to a specification the human understands; Mandel's children are asked for the specification (states, features, decode mode, refit cadence, cost model, split) before the code, and the specification is what gets reviewed.

## What Mandel holds loosely or rejects

- **"Profitable trading strategies."** No number, no out-of-sample period, no costs recovered. Recorded as an anecdote with zero insight weight.
- **"Copying top hedge funds."** The HMM is not Renaissance's edge; it is a 1960s algorithm its own inventor stopped trading with. The framing imports prestige, not evidence. Mandel keeps the technique and drops the association.
- **Hand-labelled three-state regimes (bull/bear/sideways by a ±2% or ±5% 20-day return threshold).** The threshold and window are free parameters chosen by inspection; the labels are then "fit" by counting, which looks parameter-free and is not. If Mandel uses such labels, the threshold grid is counted as trials.
- **Regime output as a direct trading signal.** `sign(P(bull) − P(bear))` on daily data with no costs is the genre's default and is, on the evidence available, untested; the HMM's honest use is conditioning.
- **Stationarity of regimes.** "Fitted regimes are not guaranteed to persist out of sample." A regime model trained on 2020–2024 prediction-market microstructure may not describe 2026's; Mandel treats regime definitions as versioned and re-validated, not discovered once.
- **Claude Code as evidence.** That an agent can write a correct `GaussianHMM` pipeline in twenty minutes says nothing about whether the pipeline has edge; the implementation layer's quality is tested with unit tests, the strategy's quality with held-out data, and the two are not interchangeable.
- **The research hint's workflow as the video's content.** CLAUDE.md conventions, tests, walk-forward and paper trading are good practice and Mandel adopts them, but they are not confirmed to be in this video. The protocol below is Mandel's, grown from the chapter structure.

## Design implications for the RSI predictive substrate

1. **`RegimeModel` registry entry** (extends the component registry from resource 12): `{component: "regime_hmm", kind: "deterministic", evaluation_method: "backtest", features: [...], n_states: K, covariance_type, n_iter, restarts: [seeds], decode: "filtered", refit_cadence: "weekly|monthly", train_window: "expanding|rolling:N", code_hash}`. `kind` is `deterministic` only because seeds are fixed and recorded; a fit without recorded seeds is `unscored`. `decode` must be `filtered`; `smoothed` or `viterbi` fits are accepted with `evaluation_method: "diagnostic"` and refused by the gate as backtest evidence.
2. **Bitemporal regime store.** `regime_states.jsonl`: `{ts, fit_id, probs: [p_1..p_K], argmax, valid_at, available_at}`, where `available_at` is the wall-clock moment the fit that emitted the row could have existed (end of its training window plus compute time). Backtests join on `available_at ≤ decision_ts`. Test: `test_regime_features_are_filtered` asserts that recomputing any stored row from data truncated at its `available_at` reproduces it; a mismatch is a hard reject with reason `smoothed_feature_leak`. This is ORIGINAL-IDEAS §1 (bitemporal substrate) given its first concrete consumer.
3. **Fit registry.** `fits.jsonl`: `{fit_id, component, train_start, train_end, θ_hash, log_likelihood, bic, seeds_tried, best_seed, label_stability_vs_prev, created_at}`. `label_stability_vs_prev` = share of the previous fit's in-sample argmax labels unchanged under the new fit; registered minimum (start at 0.90) below which the fit is logged and not promoted.
4. **Walk-forward refit protocol.** Use `walk_forward_splits` with an embargo at least as long as the strategy's holding period; at each split, fit on the training fold with the registered restarts, emit filtered probabilities over the test fold using only the frozen fit, append to the regime store, never backfill. Refit cadence, `K`, threshold grid and feature set are pre-registered in the proposal, and their product is `n_trials` for `deflated_sharpe_ratio` / `expected_max_sharpe`.
5. **State-count selection rule.** Fit `K ∈ {2,3,4}` on the training fold only; choose by BIC and by `label_stability` across two adjacent refits; record all three fits. `K` chosen by test-fold performance is a forking path and fails `strategy_improvement_criteria`.
6. **Per-regime metrics in `compare_strategies`.** Add `by_regime: {k: {n, edge, sharpe, brier, max_dd}}` and a `regime_dependence` flag when the all-sample edge is explained by one state. A regime-dependent strategy is promotable only with an attached regime gate (trade only when `P(s_t=k) ≥ τ`, `τ` pre-registered), and the gated strategy is what gets backtested.
7. **Actionability check.** For each state, `expected_duration_k = 1 / (1 − A[k,k])` (in bars). Gate rule: `min_k expected_duration_k ≥ holding_period + refit_cadence`; otherwise the regime cannot be acted on before it changes, and the proposal is returned with reason `regime_too_fast_for_costs`.
8. **Prediction-market feature set for the regime engine** (what Mandel's HMM observes, since it does not trade equity returns): daily log-change of the implied probability, realised volatility of the implied probability, bid–ask spread, volume, time-to-resolution bucket, and a news-intensity count; standardised; fit per market category. Hypothesis to pre-register: cross-platform spreads (Polymarket vs Kalshi) widen in the high-volatility state and arbitrage fill rates fall; if true, the bot's size and threshold become regime-conditional.
9. **Baselines ladder.** Every regime proposal is compared against three baselines on the same splits: no regime; counted transition matrix on a hand-labelled series (the genre's simplest version); and a rolling-volatility threshold (a one-feature regime). Promotion requires beating all three on the deflated metric; the result, pass or fail, is stored as an insight with provenance `src:13`.
10. **Claude Code protocol for children building a model component** (Mandel's protocolisation of chapters 2–5; not attributed to the video): (i) *Specify*: states, features, decode mode, refit cadence, cost model, split, baselines, `n_trials`, in a pre-registered proposal. (ii) *Core logic*: implement the component alone with unit tests, including a synthetic-data test where true states are known and recovered-state accuracy is asserted, and a leak test (step 2). (iii) *Agent implements*: Claude Code writes the pipeline against the spec; the review checks the spec, not the prose. (iv) *Validate*: walk-forward, costs, deflated Sharpe against baselines. (v) *Adjust*: integrate as conditioning only. (vi) *Paper*: the regime series is emitted live and stored before any live-money change (MANDEL.md principle 13). Repository conventions (CLAUDE.md or equivalent) state the filtered-only rule, the cost-model schema and the refit protocol so that the agent cannot "helpfully" call `predict_proba` on the full series.
11. **Metrics added to Mandel's scoreboard.** `regime_fits / regime_fits_stable`, `regime_proposals / regime_proposals_beating_baselines`, `smoothed_feature_leaks_caught`, and per-component `label_stability`.
12. **Negative-result memory.** If the HMM fails to beat the counted matrix or the volatility threshold on Mandel's markets, that is recorded as a validated negative insight ("regime model X adds nothing over Y on data Z, splits S"), and the children receive the negative result instead of the technique.

- **01 (Seife, information theory):** a regime model is a lossy compression of the return series into `log2(K)` bits per bar; the entropy of each row of `A` measures how predictable the next state is, and a row near uniform means the regime carries no information about tomorrow.
- **02 and 03 (Mossbridge, precognition and psi):** the same hygiene applies to a "prescient-looking regime plot" and to a claimed anomalous effect: ask whether the analysis could see the future (smoothing) and how many configurations were tried.

- **15 (3Blue1Brown, fractals are not self-similar) and 16 (Hubbard, Mandelbrot set):** volatility clustering is better described by multifractal (continuous, scale-dependent) roughness than by a few discrete states; an HMM is a coarse-grained approximation that may be adequate for sizing and inadequate for timing.
