## What it says (core ideas)

The arc the title and hints describe is the classical one: start with a model that is a straight line, notice that classification needs a squashing function, notice that stacking squashed linear units gives a network, notice that the network can fit anything including noise, and end with the discipline that separates fitting from learning: a split of the data into parts the optimizer sees and parts it does not. Each step below gives the mechanism and the formula.

1. **Linear regression is the base case.** [title][bg] The model is ŷ = wᵀx + b with weights w and bias b. The loss is mean squared error, L(w,b) = (1/M) Σᵢ (f_{w,b}(x⁽ⁱ⁾) − y⁽ⁱ⁾)² over M examples (the crash course's formula). The loss surface of a linear model under MSE is convex ("The loss functions for linear models always produce a convex surface"), so any local minimum is the global one and gradient descent is guaranteed to find it; a closed-form solution (the normal equations, w = (XᵀX)⁻¹Xᵀy) also exists. Everything that follows removes that guarantee one piece at a time.

2. **Logistic regression is a linear model with a probability squashed on the end.** [hint][bg] Compute the same linear score z = b + w₁x₁ + ⋯ + wₙxₙ, then pass it through the sigmoid σ(z) = 1/(1 + e^(−z)), which maps the real line onto (0,1) so the output can be read as P(y = 1 | x). Solving the sigmoid for z gives z = ln(p/(1−p)): the linear score *is* the log-odds. The decision boundary σ(z) = 0.5 is the hyperplane z = 0, so logistic regression is still a linear classifier. The loss changes from MSE to log loss (binary cross-entropy), −[y ln p + (1−y) ln(1−p)], which is convex in w for this model and is the only loss whose minimiser is the true conditional probability (a strictly proper scoring rule; see file 05, bullet 20). CS231n puts the same point as: a single neuron with a sigmoid output and cross-entropy loss "is" logistic regression ("binary Softmax"); swap in a hinge loss and it is a binary SVM.

3. **A neuron is a logistic unit; a network is neurons feeding neurons.** [title][hint][bg] A multilayer perceptron with one hidden layer computes h = g(W₁x + b₁), ŷ = W₂h + b₂ (plus a sigmoid or softmax on ŷ for classification). The hidden layer is a learned feature map: instead of choosing the features by hand, the network learns W₁ so that the problem becomes linearly separable in h-space. XOR is the canonical motivating example: no line separates {(0,0),(1,1)} from {(0,1),(1,0)}, but two hidden ReLU units do.

4. **Without a nonlinearity the stack collapses.** [title][bg] If g is the identity, ŷ = W₂(W₁x + b₁) + b₂ = (W₂W₁)x + (W₂b₁ + b₂), a single linear map. Google's phrasing: "Linear calculations performed on the output of linear calculations are also linear, which means this model cannot learn nonlinearities." CS231n's: "the two matrices could be collapsed to a single matrix," so "the predicted class scores would again be a linear function of the input." Depth buys nothing until an elementwise nonlinearity sits between the matrices. That is the whole reason activation functions exist.

5. **Sigmoid and tanh saturate; ReLU does not (on one side).** [title][bg] Sigmoid output is in (0,1), its derivative σ′(z) = σ(z)(1−σ(z)) peaks at 0.25 and is near zero for |z| large, so gradients shrink multiplicatively through layers (the vanishing-gradient problem); it is also not zero-centred. CS231n: "Sigmoids saturate and kill gradients," and it "has recently fallen out of favor and it is rarely ever used." tanh is zero-centred but still saturates; "the tanh non-linearity is always preferred to the sigmoid nonlinearity." The rectified linear unit is g(z) = max(0, z): derivative 1 for z > 0, 0 for z < 0, no saturation on the positive side, and computed by a single comparison.

6. **Why ReLU, and its one failure mode.** [title][bg] Pros: it "greatly accelerate[s]" convergence, "(e.g. a factor of 6 in Krizhevsky et al.)", it is cheap, and it "is less susceptible to the vanishing gradient problem" (Google). Con: "the ReLU units can irreversibly die during training": a unit pushed into z < 0 for every input has zero gradient and never recovers; CS231n reports that up to 40% of a network can be dead if the learning rate is too high. Leaky ReLU (small positive slope for z < 0) and Maxout are the fixes, with inconsistent gains. The standing recommendation: "Use the ReLU non-linearity, be careful with your learning rates."

7. **Universal approximation is true and nearly useless.** [bg] "Neural Networks with at least one hidden layer are universal approximators" of continuous functions, but CS231n calls this "a relatively weak and useless statement in practice": the theorem says nothing about how many units are needed or whether gradient descent will find them. Networks work because they compactly express the smooth functions real data has and because that expression is learnable; empirically, deeper networks beat equally large shallow ones.

8. **Gradient descent is the single learning rule for all three models.** [title][bg] θ ← θ − η ∇_θ L. The crash course's four steps: calculate the loss at the current parameters; determine the direction that reduces loss; move the parameters a small amount in that direction; repeat "until the model can't reduce the loss any further" (convergence: "additional iterations don't reduce loss more"). For an MLP the gradient is computed by backpropagation, which is the chain rule applied layer by layer from the loss backward (file 05 has the derivation). The learning rate η is the first hyperparameter: too small and "the improvements will be linear" and slow; too large and the loss oscillates or diverges, and ReLUs die. In practice: mini-batch SGD, momentum (coefficient around 0.9), or Adam (defaults β₁ = 0.9, β₂ = 0.999, ε = 10⁻⁸, "currently recommended as the default algorithm to use"), plus a step decay of η, or halving η "when validation error stops improving".

9. **The MLP's loss surface is non-convex.** [bg] Once a nonlinearity is present, MSE or cross-entropy in the weights has many minima and saddle points, the result depends on the random initialisation, and no step size guarantees the global optimum. The practical compensation is cheap: run several seeds, compare on held-out data, and treat the seed as a hyperparameter to be reported, not hidden.

10. **Overfitting defined.** [title][bg] Overfitting is "creating a model that matches (memorizes) the training set so closely" that it fails on new data; underfitting is a model that "doesn't even make good predictions on the training data"; generalization is the opposite of overfitting. CS231n: "Overfitting occurs when a model with high capacity fits the noise in the data." The two causes the crash course names: the training set does not represent the real data, or the model is too complex for the amount of data. Capacity is the number of distinct functions the model can represent; an MLP's capacity grows with width and depth, and a model with more free parameters than independent constraints can fit any labelling, including random ones (file 05, bullet 10: a deep network reaches the same training accuracy on shuffled labels).

11. **The generalization curve is the diagnostic.** [title][hint][bg] Plot training loss and validation loss against training iterations. "The two curves start out behaving similarly, then diverge": training loss "declines or holds steady (converges)" while validation loss "increases," which "suggests overfitting." A well-fit model shows "two loss curves that have similar shapes." CS231n on the accuracy version: "The gap between the training and validation accuracy indicates the amount of overfitting"; a large gap calls for stronger regularisation or more data; little or no gap "indicates that your model capacity is not high enough." The curve is read at the moment of divergence, not at the end of training.

12. **The hold-out method: three sets, three roles.** [hint][bg] scikit-learn states the base error: "Learning the parameters of a prediction function and testing it on the same data is a methodological mistake: a model that would just repeat the labels of the samples that it has just seen would have a perfect score but would fail to predict anything useful on yet-unseen data." Holding out a test set fixes that for *parameters* but not for *hyperparameters*: "there is still a risk of overfitting on the test set because the parameters can be tweaked until the estimator performs optimally. This way, knowledge about the test set can 'leak' into the model and evaluation metrics no longer report on generalization performance." Hence a third partition: "training proceeds on the training set, after which evaluation is done on the validation set, and when the experiment seems to be successful, final evaluation can be done on the test set." CS231n: the test set is "a very precious resource that should ideally never be touched until one time at the very end"; "Evaluate on the test set only a single time, at the very end." The validation set is "essentially used as a fake test set to tune the hyper-parameters" (e.g. 49,000/1,000 of CIFAR-10's training images).

13. **The workflow and the wear-out of the test set.** [hint][bg] Google's loop: "Train model on the training set. Evaluate model on the validation set. Tweak model according to results on the validation set. Iterate on 1, 2, and 3, ultimately picking the model that does best on the validation set. Confirm the results on the test set." And the warning: "Doing many rounds of this procedure might cause the model to implicitly fit the peculiarities of the test set"; the remedy is to collect more data to "refresh" the test and validation sets. Every look at the test set spends some of its evidential value; the number of looks is itself a quantity to track.

14. **What makes a split legitimate.** [hint][bg] A good test or validation set is "large enough to yield statistically significant testing results," "representative of the dataset as a whole," "representative of the real-world data that the model will encounter," and has "zero examples duplicated in the training set" ("The only fair test of a model is against new examples, not duplicates"). Any preprocessing fitted on the training set (scaling, imputation, feature selection) must be fitted there alone and then applied unchanged to the other sets. Generalization is only expected when examples are "independently and identically distributed," "the dataset doesn't change significantly over time" (stationarity), and "the dataset partitions have the same distribution." Random shuffling before splitting "makes partitions much more likely to be statistically similar"; sorting by date before a random split breaks this when the data are non-stationary. The crash course's own counter-example is prophetic for Mandel: a train-ticket price predictor whose users act on its advice "alter the conditions they were trained on", a feedback loop no static split can model.

15. **Time series break the i.i.d. assumption, so the split must follow time.** [bg] scikit-learn: "classical cross-validation techniques such as KFold and ShuffleSplit assume the samples are independent and identically distributed, and would result in unreasonable correlation between training and testing instances (yielding poor estimates of generalization error) on time series data. Therefore, it is very important to evaluate our model for time series data on the 'future' observations least like those that are used to train the model." TimeSeriesSplit trains on the first k folds and tests on fold k+1, so "successive training sets are supersets of those that come before them"; folds "must represent the same duration" for the metrics to be comparable. For grouped data (several samples per entity) "we need to ensure that all the samples in the validation fold come from groups that are not represented at all in the paired training fold." k-fold cross-validation averages the validation metric over folds and "does not waste too much data," but is expensive, so practitioners often "prefer to avoid cross-validation in favor of having a single validation split."

16. **The regularization toolbox.** [hint][bg] (a) L2 weight decay adds (λ/2n) Σ w² to the loss, so each step shrinks every weight by a factor (1 − ηλ/n) before applying the data gradient; the network prefers small weights, i.e. smoother functions, and λ is tuned on the validation set. L1 adds (λ/n) Σ |w| and drives weights to exactly zero (feature selection). (b) Dropout zeroes each hidden unit with probability p during training and rescales at test time, so no unit can rely on a specific co-adapted partner; it approximates averaging an exponential ensemble of thinned networks. (c) Early stopping: track validation loss each epoch and keep the parameters from the best epoch; stop after `patience` epochs without improvement. Training longer is itself a capacity increase, so the epoch count is a hyperparameter chosen on validation data. (d) Data augmentation and, above all, more data: in Nielsen's experiment (from memory, the site returned 503), a 30-hidden-unit network on 1,000 MNIST images reaches ~82% test accuracy and then flatlines by roughly epoch 280 while its training cost keeps falling smoothly and its training accuracy reaches 100%; training on the full 50,000 images lifts the same architecture to ~95%. The same chapter quotes von Neumann via Fermi: "With four parameters I can fit an elephant, and with five I can make him wiggle his trunk." CS231n's modern take: do not shrink the network to fight overfitting; "the regularization strength is the preferred way to control the overfitting of a neural network," and "you should use as big of a neural network as your computational budget allows," regularised.

17. **Hyperparameter search and sanity checks.** [bg] Search learning rate and regularisation strength on a log scale because they act multiplicatively; "randomly chosen trials are more efficient for hyper-parameter optimization than trials on a grid"; check whether the best value sits at the edge of the searched range. Before training on everything: confirm the initial loss equals the chance value (−ln(1/C), e.g. 2.302 for ten classes) with regularisation off, and "try to train on a tiny portion (e.g. 20 examples) of your data and make sure you can achieve zero cost." A pipeline that cannot overfit twenty examples is broken; a pipeline that overfits them and then also fits shuffled labels on the full set has learned nothing you can trust. Gradient checks use centred differences and relative error; "relative error > 1e-2 usually means the gradient is probably wrong."

18. **The classical U-curve is a first approximation.** [bg] The textbook picture (test error falls then rises with capacity) is incomplete for modern overparameterised networks: Nakkiran et al. (2019) document "double descent," where test error rises and then falls again as model size or training epochs increase, introduce "effective model complexity" to unify the two, and "identify certain regimes where increasing (even quadrupling) the number of train samples actually hurts test performance." For small tabular and time-series models of the kind Mandel's children will mostly run, the classical picture remains the right default; the point is that the shape of the generalization curve is an empirical question, measured on held-out data, not a law to be assumed.

19. **The creator's own applied practice shows how hard the discipline is to keep.** [creator] The *Clean Energy* 2025 paper (FCM-CNN-WNN-WBiLSTM with attention, trained with RMSprop and MAE loss on NASA and CALCE battery datasets, min–max normalised) splits by battery identifier into training and test batteries (e.g. B0005/6/7 train, B0018 test), uses dropout 0.4 as the only named regulariser ("Prevents overfitting by regularization"), labels its architecture choices "optimal hyperparameters" without describing how they were selected, reports no validation set, no early stopping, no epoch count, no batch size and no training-versus-test curves, and presents headline test errors (RMSE 0.0013, MAPE 0.0015) that conflict with the conclusion's figures (RMSE 0.002, MAPE 0.13). Several table rows report MAE larger than RMSE, which is impossible for the same series (RMSE ≥ MAE always), so at least one column is mis-transcribed. None of this is unusual for applied deep-learning papers, and it is not a claim about the video. It is a measured example of the distance between teaching "tune on validation, touch the test set once" and practising it under publication pressure, which is the distance Mandel's gate exists to close mechanically rather than by exhortation.

## What Mandel adopts

1. **A score computed on data the optimiser has seen is not evidence, for any model including Mandel itself.** Because scikit-learn's base statement ("testing it on the same data is a methodological mistake ... a perfect score") applies to a proposal tuned against the same backtest window that is then used to accept it; `gate.evaluate` already refuses evidence without `out_of_sample=True`, and this file is the reason that flag exists.
2. **Three partitions with three roles: train (fit), validation (choose), test (confirm once).** Because hyperparameter selection on the test set leaks knowledge of it into the model, and in Mandel every proposal is a hyperparameter of the system; children tune on validation folds, and the gate's final out-of-sample period is a test set that each proposal may consult once.
3. **Count the looks at the hold-out and treat the count as a cost.** Because "the more you use the same data to make decisions ... the model implicitly fits the peculiarities of the test set"; `n_trials_declared` already caps trials per proposal, and the same counter should run per hold-out period across proposals, with the deflated Sharpe ratio's trial count fed from it.
4. **The in-sample versus out-of-sample gap is the overfitting metric, reported on every run.** Because "the gap between the training and validation accuracy indicates the amount of overfitting" and the moment the two curves diverge is the diagnostic; a `gap_ratio` (out-of-sample loss over in-sample loss) belongs next to `brier_delta` and `sharpe_diff` in the evidence dict, with a reject threshold.
5. **Early stopping is the default stopping rule for any iterative improvement loop.** Because training longer is a capacity increase and the epoch at which validation loss turns is chosen on validation data; a child's or Mandel's own refinement loop halts after `patience` rounds without validation improvement and reverts to the best-validation state, never to the last state.
6. **Prefer regularisation over a smaller search space, but declare the regulariser before seeing results.** Because "the regularization strength is the preferred way to control the overfitting," and because λ, dropout rate and early-stopping patience are hyperparameters that would otherwise be tuned on the test set; they go into the pre-registered criteria body that `compute_criteria_hash` covers.
7. **Splits follow time and carry an embargo; random shuffles are forbidden on market data.** Because KFold and ShuffleSplit "would result in unreasonable correlation between training and testing instances" under autocorrelation and the right test observations are "the 'future' observations least like those that are used to train the model"; `walk_forward_splits(n, n_splits, min_train, embargo)` is the only splitter the gate accepts, and `embargo` must exceed the label horizon.
8. **Grouped entities stay on one side of the split.** Because validation samples must "come from groups that are not represented at all in the paired training fold"; for Mandel the groups are markets that resolve on the same event (and the same event across venues), which otherwise leak outcomes between train and test.
9. **Fit all preprocessing on the training partition only.** Because the same transformation must be applied to "the validation set, test set, and real-world dataset" and fitting a scaler, a feature selector or a liquidity filter on the whole history is a leak; the gate's evidence should name the fit window of every transform.
10. **Stationarity is an assumption to test, not a given, and the feedback loop is real.** Because generalization is only promised when "the dataset doesn't change significantly over time" and the crash course's own ticket-pricing example shows predictions changing the thing predicted; every validated result carries `as_of`, is re-validated on a rolling window, and strategy backtests include a cost-and-impact model.
11. **Positive and negative controls before any real run.** Because "train on a tiny portion ... and make sure you can achieve zero cost" catches broken pipelines, and a model that also fits shuffled labels has learned nothing; a child's pipeline must recover a planted signal on synthetic data and must find no edge when outcomes are permuted within time blocks.
12. **Chance-level baselines are explicit numbers, computed first.** Because the initial loss should equal −ln(1/C) at chance; for Mandel the reference is the market price at forecast time (`skill_vs_market`) and the constant-0.5 Brier of 0.25, and a proposal is scored only against those stated baselines.
13. **Metric-consistency invariants are gate checks.** Because the creator's own paper reports MAE larger than RMSE, which cannot happen for one series; the gate rejects evidence where RMSE < MAE, Brier ∉ [0,1], log loss < 0, or `MurphyDecomposition.reconstructed` disagrees with the Brier score beyond tolerance, before looking at any threshold.
14. **Log-scale, random hyperparameter search with declared ranges, and a check of the range edges.** Because learning rate and regularisation strength act multiplicatively and random search beats grid search; Mandel's sweeps declare the range in the proposal and flag a winner that sits at a boundary as "search not finished" rather than as a result.
15. **Seeds are hyperparameters and are reported.** Because the MLP's loss surface is non-convex and the result depends on initialisation; any child result that cannot be reproduced across seeds within its own confidence interval is a seed effect, and the ledger records the seed with the run.
16. **Capacity is budgeted against independent observations.** Because a model "with high capacity fits the noise in the data" and von Neumann's elephant needs only four parameters; each child strategy records its free-parameter count (rules, thresholds, features) against the number of independent out-of-sample periods, and a ratio that would let it fit any labelling is a reason to shrink or regularise before testing.

## What Mandel holds loosely or rejects

- **Anything attributed to this video specifically.** The transcript was not reachable; the content above is the canon the title names. Hold the attribution loosely, hold the content firmly.
- **"Shuffle, then split" as the default split.** Correct for i.i.d. data, wrong for Mandel's: the crash course itself concedes that a random split of date-sorted non-stationary data misleads. Rejected for market data in favour of time-ordered, embargoed splits.
- **"Collect more data" as the first remedy for overfitting.** True in the lecture's regime; in Mandel's, more history means older regimes, and more markets means more correlated resolutions. More data helps only when it is from the same distribution, which must be shown, not assumed.
- **The classical U-shaped capacity curve as a law.** Double descent (Nakkiran et al. 2019) shows test error can fall again past the interpolation threshold and that more samples can hurt in some regimes. Mandel measures the generalization curve on its own data rather than assuming its shape; for small tabular models the classical picture is the right prior.
- **k-fold cross-validation.** Attractive for thin data but it violates time order; use it only in its time-series form (`walk_forward_splits`) and never with shuffling. A single validation split is acceptable when the fold design is honest and declared.
- **"Use as big a network as your budget allows."** CS231n's advice presumes abundant data and a stationary target. For Mandel's children, capacity is a liability per independent observation; the advice is reversed to "use the smallest model that reaches the validation target, regularised."
- **Universal approximation as a reason to expect a network to learn anything.** The theorem says nothing about learnability from finite, noisy, non-stationary data; Mandel does not treat architectural expressiveness as evidence of predictive power.
- **ReLU as universally better.** It is the default for deep networks; dying units and the learning-rate coupling are real, and for the shallow or linear models Mandel's children will mostly run, the choice of activation is a second-order concern next to the split design.
- **The creator's applied papers as methodological templates.** They are competent domain work, but the protocol they report (train/test only, no validation set, undocumented hyperparameter selection, inconsistent tables) is exactly what the lecture's own lesson warns against; Mandel takes the lesson, not the practice.
- **Any claim that the creator's teaching goes beyond the canon.** With coverage at 0.35, assume it does not until shown otherwise.

## Design implications for the RSI predictive substrate

- **Three-way temporal partition as a first-class object.** Define `Partition(train: (t0,t1), validation: (t1+embargo, t2), test: (t2+embargo, t3), embargo: int, fit_windows: dict[transform_name, (t0,t1)])` and attach its hash to every piece of evidence; `gate.evaluate` rejects evidence whose partition hash is missing or whose `test` window has been consulted by a prior proposal more than once without a declared re-registration.
- **Hold-out touch ledger.** Add a `holdout.touch` event to `state/ledger.jsonl` with `{period_id, proposal_id, metric_names}`; expose `touches(period_id)` and feed it as `n_trials` into `expected_max_sharpe` / `deflated_sharpe_ratio`, so the DSR's trial count reflects every look at that period across proposals, not only within one.
- **Gap metric in the evidence dict.** For strategies: `gap_ratio = oos_loss / is_loss` with loss = negative mean return or log loss as appropriate; for forecasters: `gap_ratio = brier_oos / brier_is`. Add `Criterion("gap_ratio", "<=", 1.5)` to `strategy_improvement_criteria` and `forecast_improvement_criteria` (threshold pre-registered per proposal); also record `is_score` and `oos_score` separately so the ratio can be audited.
- **Generalization curve over cycles.** In `cycles.jsonl`, record per cycle the incumbent's in-sample and out-of-sample metric on the current rolling window; a divergence of the two series (out-of-sample worsening for `patience` cycles while in-sample improves) opens a review proposal automatically, mirroring the loss-curve diagnostic.
- **Early-stopping protocol for iterative proposals.** A proposal that iterates (a child refining a strategy, Mandel tuning a weight) declares `patience` and `max_rounds` in its criteria body; the loop stops at the first of the two, and the adopted state is the best-validation round, with the round index logged.
- **Walk-forward is the only splitter.** `walk_forward_splits(n, n_splits, min_train, embargo)` remains the single supported splitter; add a validation that `embargo >= label_horizon` and a `GroupedWalkForward` variant whose groups are event identifiers, so markets resolving on the same event (and cross-venue twins) never straddle a split.
- **Preprocessing fit-window audit.** Every transform in a child's pipeline reports `fit_window`; the gate rejects evidence where any `fit_window` end exceeds the training window end. This covers scalers, imputers, feature selection, liquidity filters and any lookup table built from history.
- **Controls as gate steps.** Add `positive_control_passed` (planted-signal recovery on synthetic data) and `shuffle_p` (one-sided p-value of the observed edge against a within-block outcome permutation null, blocks matching the embargo) to the evidence dict; `Criterion("shuffle_p", "<=", 0.05)` and `Criterion("positive_control_passed", "==", 1.0)` join the standard criteria sets.
- **Metric invariants before thresholds.** In `gate.evaluate`, before iterating criteria, run `check_invariants(ev)`: RMSE ≥ MAE where both present; 0 ≤ Brier ≤ 1; log loss ≥ 0; `murphy_decomposition(...).reconstructed ≈ brier_score(...)` within 1e-6; `n_resolved` equals the length of the scored pairs. A failed invariant is a hard reject with the reason "evidence internally inconsistent."
- **Declared baselines.** The evidence dict names its reference: `baseline_kind ∈ {market_price, constant_0.5, incumbent}` and `baseline_score`; `skill_vs_market` and `brier_skill_score` are computed only against the declared reference, and a proposal that changes its baseline after pre-registration fails `check_integrity`.
- **Regulariser and search ranges inside the criteria hash.** Extend the body hashed by `Proposal.compute_criteria_hash` with `regularisation` (type and strength), `search_space` (per-hyperparameter ranges and scale), `patience`, and `seeds`; a winner at a range boundary sets `search_complete=False` and the gate returns "not decided" rather than pass or fail.
- **Capacity record per child.** `children.py` stores `free_parameters` (count of tunable rules, thresholds, features and weights) and `independent_oos_periods`; the ratio is shown in the scoreboard and a ratio above a declared ceiling is a review flag, not a pass/fail, since the right ceiling is itself an empirical question.
- **Stationarity and impact.** Every `SourceScore` and strategy result carries `as_of` and `window`; the gate re-validates incumbents on each new rolling window and demotes any whose out-of-sample score falls outside the confidence band of its original acceptance; strategy backtests must include a declared cost-and-impact model, because Mandel's own trades are part of the data-generating process (the ticket-pricing feedback loop).
- **Loss choice by target type.** Binary market outcomes are scored with `log_loss` as the primary metric (proper, convex for the logistic unit) and `brier_score` as the companion, consistent with file 05's adoption; MSE is reserved for continuous targets. The reason is recorded with the scoring module so children do not re-derive it.
- **Legibility over depth.** The lecture's progression (linear → logistic → MLP) is also Mandel's model-selection order: start with the linear or logistic model, adopt a deeper one only when it beats the simpler one on the validation partition by the pre-registered margin and survives the same controls. Each step up in capacity is a proposal with its own gate pass, never a default.
