## What it says (core ideas)

The series has one thesis stated in chapter 2 and never abandoned: "once you see how it works, it feels a lot less like some crazy sci-fi premise and a lot more like a calculus exercise. It really just comes down to finding the minimum of a specific function." Everything else is mechanism.

1. **A neuron is "a thing that holds a number", and a layer is a function.** [Ch1] The MNIST network: 784 input activations (28×28 pixel brightnesses in [0,1]), two hidden layers of 16 ("admittedly kind of an arbitrary choice"), 10 outputs. Each neuron in a layer computes a weighted sum of the previous layer plus a bias, squashed by a nonlinearity: a_j^(1) = σ(w_{j,0} a_0^(0) + w_{j,1} a_1^(0) + ⋯ + w_{j,n} a_n^(0) + b_j). In matrix form a^(1) = σ(W a^(0) + b), "which makes code cleaner and faster" because matrix multiplication is what libraries optimise. The whole network is a function R^784 → R^10 with 784·16 + 16·16 + 16·10 = 12,960 weights and 16 + 16 + 10 = 42 biases: **13,002 "knobs and dials"**.

2. **Why the pieces are there.** [Ch1] Weights say how much one activation pushes the next (positive blue, negative red; a positive patch surrounded by negative weights makes an edge detector). The bias sets "how large the sum must be before the neuron becomes meaningfully active" (example bias −10). Sigmoid σ(x) = 1/(1+e^(−x)) maps R → (0,1); the lesson notes it flattens at the extremes, which slows training, so "modern networks often use ReLU" (max(0,x)) instead. Without a nonlinearity the stack collapses to a single linear map and loses all expressiveness. Neural networks are brain-inspired but "by no means identical", "birds versus airplanes".

3. **The layered-features hope is stated as a hope, then tested, then found false.** [Ch1][Ch2] The hoped-for story is first layer = edges, second = loops and lines, output = digits. After training, the second-layer weight grids "look, well, almost random … some loose patterns, but hardly the ones we might expect"; the neurons respond to "some strange blobby shapes". The network still gets "about 96%" of new images right (about 98% with other hidden-layer sizes; modern networks 99.75%). It found "a happy little local minimum" in 13,002 dimensions that classifies most images "but doesn't capture more generalizable patterns".

4. **Learning is minimising a declared cost.** [Ch2] Initialise all 13,002 parameters at random ("the output layer just looks like a mess"). For one example, cost = Σ_j (a_j^(L) − y_j)^2, the squared gap between the output activations and the one-hot target. The total cost C is the average over all training examples. "The training data is a massive set of parameters to the cost function": the network is a function of pixels with 13,002 parameters; the cost is a function of the 13,002 parameters with tens of thousands of images as its parameters. Performance is checked on "some other data it's never seen before", i.e. a held-out set, from the first mention of training.

5. **Gradient descent and what the gradient means.** [Ch2] Solving ∇C = 0 analytically is infeasible, so: compute the gradient, step downhill, repeat. ∇C points uphill and its length is the steepness; each step is −η∇C with learning rate η ("bigger steps … but there's a risk of overshooting and oscillating"). Steps proportional to slope shrink near a minimum and prevent overshoot. There is no guarantee the local minimum reached is the global one; where you land depends on the random start. The non-spatial reading: write all 13,002 parameters as one column vector; the negative gradient is another 13,002-vector whose **sign** says which way to nudge each knob and whose **relative magnitudes** say which knobs matter most ("the gradient encodes the relative importance of each weight and bias … which changes will carry the most bang for your buck"; the Ch3 example: a component 32× larger means the cost is 32× more sensitive to that weight). The cost must be smooth, "which is why artificial neurons have continuously ranging activations rather than simply being active or inactive".

6. **Backpropagation, intuitively.** [Ch3] For a single training image of a 2, the desired output nudges are proportional to each output's distance from its target. An output activation can be raised three ways: (i) increase its bias; (ii) increase the weights, most effectively on the connections from the brightest previous-layer neurons, so the weight change is proportional to the input activation ("neurons that fire together wire together", with the caveat that the analogy "is not perfect" and the untrained network is not "thinking" about a 2); (iii) change the previous layer's activations, in proportion to the weights (brighten positively weighted neurons, dim negatively weighted ones). Each output neuron's desires for the previous layer conflict, so they are **summed**, then the same procedure recurses backward layer by layer. Averaging the per-example nudges over all examples gives, "loosely speaking", the negative gradient.

7. **Stochastic gradient descent.** [Ch3] Averaging over every example per step is too slow, so shuffle the data into mini-batches (e.g. 100) and take one approximate step per batch: "a drunk man stumbling aimlessly down a hill but taking quick steps" rather than "a carefully calculating man who takes slow, deliberate steps". The steps are "not the most efficient steps downhill" but far cheaper, and after one pass every example has influenced the parameters.

8. **Backpropagation, exactly.** [Ch4] With one neuron per layer and z^(L) = w^(L) a^(L−1) + b^(L), a^(L) = σ(z^(L)), C_0 = (a^(L) − y)^2: ∂C_0/∂w^(L) = (∂z^(L)/∂w^(L))(∂a^(L)/∂z^(L))(∂C_0/∂a^(L)) = a^(L−1) · σ′(z^(L)) · 2(a^(L) − y). Likewise ∂C_0/∂b^(L) = σ′(z^(L)) · 2(a^(L) − y) and ∂C_0/∂a^(L−1) = w^(L) · σ′(z^(L)) · 2(a^(L) − y), which is what lets the recursion continue to earlier layers. Over the dataset ∂C/∂w^(L) = (1/n) Σ_k ∂C_k/∂w^(L). With many neurons per layer (k indexes layer L−1, j indexes layer L), z_j^(L) = Σ_k w_{jk}^(L) a_k^(L−1) + b_j^(L), and because a_k^(L−1) reaches the cost through every neuron of layer L, ∂C_0/∂a_k^(L−1) = Σ_j w_{jk}^(L) σ′(z_j^(L)) 2(a_j^(L) − y_j). Three readings: a weight matters more when its input neuron is more active; the output's sensitivity is proportional to the gap between actual and desired; backprop is the chain rule applied backward through a dependency tree.

9. **Overconfidence and the limits of discriminative learning.** [Ch2] Fed random noise, the trained network "confidently predicts that this random noise is a 5"; the author expected either no strong activation or activation spread evenly, "since a truly intelligent system would show uncertainty". "Even if this network can recognize digits, it has no idea how to draw them." The cost function "gave no incentive to be anything but confident"; the data was tightly constrained (centred, uniform size); the architecture ignores that neighbouring pixels are related and cannot transfer a pattern learned in one region of the grid to another. This is "old technology, the kind researched in the '80s and '90s … not meant to be an end goal, but instead a starting point"; convolutional networks are named as the fix.

10. **Memorisation versus structure.** [Ch2][bg] The video (not the companion page) discusses the finding that a deep network trained on randomly shuffled labels still reaches the same training accuracy, so fitting the training set proves nothing about having learned structure ("Understanding deep learning requires rethinking generalization", Zhang et al. 2017), and a follow-up showing that on correctly labelled data the training cost falls much faster than on random labels, suggesting the minima found on structured data are qualitatively different (I believe this is Arpit et al. 2017, "A Closer Look at Memorization in Deep Networks"; the attribution is from memory). Michael Nielsen's free book is recommended as "the best next step", with Chris Olah's blog and Distill as further reading.

11. **A transformer is a next-token probability function run in a loop.** [Ch5][LLM] GPT = Generative Pre-trained Transformer. The model maps text (possibly plus images or audio) to a probability distribution over the next token; generation samples from it, appends, and repeats, which is why a deterministic function gives different answers on different runs. A chatbot is this loop applied to a script that opens with a system description of an assistant followed by the user's turn. Pipeline: tokenise → embed each token as a vector → alternate **attention** blocks (vectors exchange information) and **MLP** blocks (each vector is transformed independently, in parallel) many times ("puts the 'deep' in deep learning") → **unembed** the last vector to one score per vocabulary entry (logits) → softmax to probabilities.

12. **GPT-3 by the numbers.** [Ch5][Ch6][Ch7] Vocabulary 50,257; embedding dimension 12,288; context 2,048 tokens; 96 layers; 96 attention heads per layer; key/query dimension 128; MLP hidden width 49,152 = 4 × 12,288. The 175 billion parameters sit in "just under 28,000 matrices" in eight categories. Counts stated on the companion pages: embedding 50,257 × 12,288 = 617,558,016; unembedding the same; each W_Q and W_K 12,288 × 128 ≈ 1.57M; one head's four matrices ≈ 6.3M; one attention block ≈ 600M; all attention "just under 58 billion" (≈ 1/3); each MLP up- or down-projection ≈ 604M, ≈ 1.2B per block, ≈ 116B total ("around two-thirds"). Multiplying out the stated dimensions gives the per-category table the video shows on screen: embedding 617,558,016; key 14,495,514,624; query 14,495,514,624; value 14,495,514,624; output 14,495,514,624; up-projection 57,982,058,496; down-projection 57,982,058,496; unembedding 617,558,016; total **175,181,291,520**. Biases and normalisation parameters are called negligible.

13. **Embeddings: directions carry meaning, measured by dot products.** [Ch5] The dot product is positive for aligned vectors, zero for perpendicular, negative for opposed. E(woman) − E(man) ≈ E(queen) − E(king) is "a classic example" that the author's own model gets only approximately ("queen" is "a little farther off than the difference suggests", plausibly because queens are not merely female kings in the training text); E(Hitler) + E(Italy) − E(Germany) lands very close to E(Mussolini); E(cats) − E(cat) gives a plurality direction along which plural nouns score higher. All of this is framed as "it seems as if", observations on one model rather than proven mechanism. The initial embedding carries word and position only; context is added by attention.

14. **Attention, one head.** [Ch6] Motivating cases: "mole" in three sentences has one initial embedding and three meanings; "tower" after "Eiffel" should move toward the Eiffel Tower and after "miniature" away from "large, tall things"; in a mystery novel the final "was" must have absorbed the whole passage. Each embedding E_i is multiplied by W_Q to give a query Q_i ("are there adjectives in front of me?") and by W_K to give a key K_i (a candidate answer); both live in a 128-dimensional space. The grid of dot products K_j · Q_i is the **attention pattern**; softmax is applied **down each column** so each query's weights sum to 1. For autoregressive training "the model predicts the next token at every position at once", so later tokens must not inform earlier ones: those entries are set to −∞ before the softmax (causal masking), which zeroes them. Each embedding also gives a value V_j = W_V E_j, "the adjustment a word should make to another word's embedding"; the update is ΔE_i = Σ_j softmax_j(K_j·Q_i) V_j and E′_i = E_i + ΔE_i. Compactly, Attention(Q,K,V) = softmax(QKᵀ/√d_k) V. W_V is factored as value-down (12,288 → 128) times value-up (128 → 12,288), a low-rank map; the value-up matrices of all heads are stacked into the block's **output matrix**. The adjective-noun head is "a made-up example"; what a real W_Q does to non-noun embeddings "is unknown".

15. **Multi-head, scale, and the context bottleneck.** [Ch6] 96 heads run in parallel, each proposing a ΔE for every token; all proposals are summed and added to the embedding. Cross-attention (translation) takes keys and queries from different sequences and usually has no mask. The attention pattern has one row and one column per token, so its size grows with the **square** of the context length, which "makes context length a major limitation"; variants exist to make it scale. Attention is highly parallel and GPU-friendly, and the author ties the field's progress to scale.

16. **MLPs as fact storage, and why single neurons are not features.** [Ch7] A DeepMind result (Dec 2023) locates the fact "Michael Jordan plays basketball" mainly in the MLP blocks. Idealised mechanism: the up-projection W↑ (49,152 × 12,288) plus bias B↑ asks each row's "question" of the input vector by dot product; ReLU (or GELU in practice) zeroes negatives so a neuron acts like an **AND gate** that fires only when both the Michael and the Jordan directions are present; the down-projection W↓ (12,288 × 49,152) plus B↓ adds back a column vector (e.g. the basketball direction) scaled by that activation; the result is added to the residual stream, in parallel for every token. The example "does not claim to reflect how real models store facts". **Superposition:** only n vectors can be exactly perpendicular in n dimensions, but allowing nearly perpendicular vectors (85°–95°) lets the number of distinguishable directions grow exponentially with dimension (Johnson–Lindenstrauss). The author's own demo (10,000 vectors in 100 dimensions "between 89 and 91 degrees") had a bug in its cost function; the correction says 100 dimensions are not enough for that range, and a viewer's figures (Nick Yoder) give: 89°–91° needs more than 250,000 dimensions; at 85°, 12,288 dimensions hold over 40 billion vectors; 116,000 dimensions hold over 10^100. Consequence: features are combinations of neurons, individual neurons rarely mean one thing, and sparse autoencoders are the tool interpretability researchers use to recover the features (Anthropic's "Toy Models of Superposition" and dictionary-learning work are cited).

17. **Softmax, logits, temperature.** [Ch5] softmax turns arbitrary scores into probabilities in (0,1) summing to 1 by exponentiating each and normalising; with temperature T the exponent is z_i/T: softmax(z)_i = e^(z_i/T) / Σ_j e^(z_j/T) (the page describes this in words; the formula is the standard one). Larger T spreads weight toward lower scores; smaller T lets the maximum dominate; at T = 0 all weight goes to the argmax. Only the **last** vector is unembedded at inference, because training is more efficient when every position predicts the token after it.

18. **Training and its scale, from the LLM short.** [LLM] Pretraining: feed all but the last word, compare the predicted distribution to the true word, backpropagate so the true word becomes slightly more likely; repeat over "many, many trillions of examples". A human reading GPT-3's training text would need "over 2,600 years" non-stop; at a billion arithmetic operations per second the training compute would take "well over 100,000,000 years". Parameters are tuned, not programmed, which is why "it's very difficult to explain why the model produces the exact prediction it does". RLHF: workers flag unhelpful outputs and the corrections adjust the parameters toward preferred responses. Transformers replaced word-at-a-time models (pre-2017) because they ingest the whole sequence in parallel on GPUs.

19. **Entropy and cross-entropy as compression cost.** [CE1][CE2] Part 1 asks "What is the fundamental compressibility of language?" and rederives information −log₂ p and entropy H(P) = −Σ p log₂ p as the minimum average bits per symbol (Shannon's noiseless coding theorem), via a robot on a distant moon receiving up/down/left/right with probabilities 1/2, 1/4, 1/8, 1/8 and optimal code lengths 1, 2, 3, 3 bits. Part 2: if the plan rotates so the true probabilities are 1/8, 1/8, 1/4, 1/2 but the old code is kept, the average rises to **2.625 bits**. Cross-entropy H(P,Q) = −Σ_x P(x) log₂ Q(x) is "how well does a code optimized for one setting, Q, perform in a different setting, P?"; with P fixed it "takes on its smallest possible value when Q is equal to P", namely H(P). Decomposition H(P,Q) = H(P) + D_KL(P‖Q): KL is the wasted bits from a mismatched code, zero iff P = Q, asymmetric (P = 90/10 against Q = 50/50 costs 1 bit; swapped, about 1.74 bits). Fractional bits are meaningful because information adds over symbols.

20. **Why the LLM loss is cross-entropy, and distillation.** [CE2] The pretraining loss is the average over training tokens of −log of the probability the model gave the true next token; with a one-hot target the cross-entropy "reduces to just the negative log of the probability the model gives to the true next token". The log is **forced**: if you want a loss minimised only when the model matches the data's statistics, the function F in Σ P·F(Q) must be a logarithm (i.e. only the log yields a strictly proper objective). Distillation trains a small model against the large model's **full distribution** with cross-entropy, "a richer signal than comparing to a single true next token". A 2002 paper recovered language family trees by gzip co-compression (compress A alone vs A with a snippet of B), "kind of like an empirical estimate of cross entropy", with the caveats that gzip is far from the Shannon limit and the paper's metric is not literally a cross-entropy between two distributions. "Whenever you see cross-entropy pop up, there will be a way to connect it to compression." Part 3 (not yet released as of research date) is to show how any predictor can be turned into a compressor whose bit count matches the model's information estimate, making cross-entropy loss equivalent to training the best text compressor.

21. **Guest lesson.** [bg] The Welch Labs video covers "diffusion models, CLIP, and the math of turning text into images"; no further content was recoverable here, so nothing below depends on it.

## What Mandel adopts

1. **Learning is minimising a declared cost on data the learner has not seen; nothing else is learning.** Because the series defines "learning" as changing parameters to lower a pre-stated cost and checks it on held-out data from the first lesson, and Mandel's whole self-improvement loop already reduces to this (proposal = parameter change, criteria = cost, gate = held-out check).
2. **The cost comes first and is frozen.** Because the cost function is a layer above the model and the gradient a layer above that; nothing downstream is meaningful if the cost is chosen after the result, which is why `Proposal.compute_criteria_hash` must precede any evidence.
3. **Log loss in bits as the primary forecast score, with Brier as the companion.** Because Part 2 shows the log is the only form whose minimiser is the true distribution (a strictly proper rule), and bits have a direct reading: the price Mandel pays for being wrong, in excess code length.
4. **Decompose every score into irreducible entropy plus model error.** Because H(P,Q) = H(P) + KL(P‖Q): a bad log loss on a coin-flip market is mostly entropy, not a bad model; Mandel should report the KL (or Murphy reliability/resolution) part, which is the only part a proposal can improve.
5. **Rank what to change by sensitivity, not by novelty.** Because the gradient's components are "which changes carry the most bang for your buck"; Mandel has no gradient but can estimate the cost sensitivity of each knob by ablation and should spend proposals where the estimated |∂cost/∂knob| is largest.
6. **Cheap noisy steps to explore, one exact step to adopt.** Because mini-batch SGD trades per-step accuracy for many more steps and still converges; Mandel's cycles should run many cheap partial-data checks to steer, but the gate's accept decision uses the full held-out set ("full batch").
7. **Step size shrinks as the slope flattens.** Because −η∇C with steps proportional to slope prevents overshoot; Mandel bounds how much changes per cycle and lowers the bound when the recent improvement-per-cycle falls.
8. **Confidence on noise is a bug, not a feature: measure it.** Because the trained network says "5" with high confidence to random pixels and "the cost function gave no incentive to be anything but confident"; Mandel's forecasts carry an out-of-distribution flag and are calibrated separately on OOD slices, and a child that is confident on scrambled inputs fails review.
9. **A permuted-labels control in the gate.** Because a network can fit random labels to the same training accuracy, so training fit is not evidence; any proposal whose edge survives when outcomes are shuffled within time blocks is measuring leakage or noise, and is rejected.
10. **Expected internal structure must be tested, not assumed.** Because the author expected edge detectors and found "strange blobby shapes" at 96% accuracy; Mandel does not trust its own story about why a child's model works until an ablation shows the named feature carries the performance.
11. **Causal masking is the backtest rule.** Because training sets every future entry to −∞ before the softmax so no position sees what comes after it; `walk_forward_splits` and every feature pipeline must enforce the same mask, and any feature computed with information dated after the forecast time is a leak.
12. **Teach children with full distributions, not verdicts.** Because distillation against the teacher's whole distribution is "a richer signal" than a single hard label; when Mandel passes a conclusion to a child it passes the probability, the alternatives considered, and the evidence weights.
13. **One claim per insight, monosemantic by construction.** Because superposition makes neural features uninterpretable (features are combinations of neurons) and sparse autoencoders are needed to undo it; Mandel's advantage over weights is legibility, so its store forbids compound insights and splits them on ingest.
14. **Context is quadratic and finite; the last vector must carry everything.** Because attention cost grows with the square of context length and only the final vector is unembedded; Mandel's synthesis-first loading order and end-of-session write-down are the same discipline applied to a session's context window.
15. **Temperature is an explicit exploration knob.** Because softmax(z/T) moves smoothly from argmax (T→0) to uniform; Mandel samples which proposal to run next with a declared temperature, logged with the run, rather than always taking the top-ranked idea or picking at random.
16. **Birds versus airplanes.** Because the series insists networks are brain-inspired, not brain-copies; Mandel borrows fractal, neural or biological structure only where it lowers a measured cost, and records the measurement.
17. **Say "calculus exercise", not "intelligence".** Because the series' honesty about what learning is ("finding lower and lower points on a specific function") is the right register for Mandel's own claims about itself.

## What Mandel holds loosely or rejects

- **"Compression is intelligence" as a design principle.** Part 2 only establishes that cross-entropy training is a compression objective and defers the equivalence proof to Part 3; even if exact, compressing past market text is not forecasting resolved outcomes under non-stationarity. Hold as a metaphor and a useful metric (excess bits), not a goal.
- **The gradient-descent picture as a description of Mandel's own learning.** Mandel has no differentiable parameters; its loop is discrete search over proposals with a black-box cost, closer to evolution or hill-climbing (see #04) than to backprop. The sensitivity and step-size ideas transfer; the efficiency of backprop does not, so Mandel's budget per improvement is far higher than a gradient step and must be spent accordingly.
- **Any claim that a particular head or neuron "does X".** The author flags every such claim as hypothetical; interpretability of children's models (or of frontier models Mandel runs on) should be treated as unresolved.
- **The 2017 generalisation discussion as current.** Double descent, grokking, scaling laws and the modern understanding of implicit regularisation postdate it; use the series for the mechanism, not for the state of knowledge about why deep nets generalise.
- **Local minima as the central difficulty.** The chapter-2 picture of valleys is pedagogical; in high dimensions saddle points and flat regions dominate and the minima found are typically fine. For Mandel the real analogue is not "stuck in a valley" but "measuring the wrong valley" (proxy metrics), which the series does not address.
- **Playlist membership of the 2025–2026 lessons.** Inferred from the website's topic ordering, not from the YouTube playlist; if the user's playlist stops at the LLM short, bullets 19–20 are still correct about the lessons but are not what the user pointed at.
- **The memorisation-paper attribution (bullet 10).** From memory; verify against the video description before citing.

## Design implications for the RSI predictive substrate

- `validation/scoring.py`: report `log_loss` in base 2 ("bits") alongside the current natural-log version, and add `excess_bits(probs, outcomes, reference_probs)` = mean(−log₂ q_mandel) − mean(−log₂ q_market), the cross-entropy gap between Mandel and the market's implied distribution; a strategy with non-negative excess bits over the market has no edge regardless of accuracy.
- `validation/scoring.py`: expose the KL/entropy split explicitly: for each forecast set compute H(outcomes | bins) as the irreducible floor and report `log_loss − floor` as the improvable part; proposals are judged on the improvable part, and `forecast_improvement_criteria` should reference it rather than raw log loss.
- `validation/gate.py`: add a mandatory negative control to `strategy_improvement_criteria`: re-run the candidate with outcomes permuted within walk-forward blocks (n_perm ≥ 200) and require the real result to beat ≥ 95% of permuted results; a candidate whose "edge" survives permutation is leaking future information or fitting noise, exactly as a network that fits random labels proves nothing by fitting.
- `validation/backtest_eval.walk_forward_splits`: document and assert the causal mask: every feature used at time t must be timestamped ≤ t; add a leak test that shifts features one step into the future and requires performance to collapse (if it does not, the features were not predictive to begin with).
- Forecast records (`forecasts.py`): add fields `ood_score` (distance of the input features from the training distribution, e.g. Mahalanobis or quantile-based) and `abstained: bool`; calibration tables are computed per OOD decile, and a child whose high-confidence forecasts cluster in the high-OOD deciles is flagged, mirroring the noise-classified-as-5 failure.
- Proposal selection (`proposals.py` / `cycles.py`): maintain a `sensitivity` map knob → estimated |Δcost| from recent ablations; the next proposal is sampled with softmax(sensitivity/T) at a logged temperature T (default 1.0, lowered when the acceptance rate is high, raised when it stalls), so exploration is explicit and reproducible.
- Cycle budget rule (`cycles.py`): at most k changes adopted per cycle, with k shrinking (k ← max(1, k/2)) whenever the mean improvement over the last N cycles falls below a declared threshold, the discrete analogue of slope-proportional steps that prevents overshoot into a regime the held-out set cannot detect.
- Two-tier evaluation in `cycles.py`: a cheap "mini-batch" pass (random 20% of the held-out set, used only to order and prune candidates) and a full pass (100% of held-out, used only by the gate); never let a mini-batch result reach `decide`.
- Knowledge store (`store.py`): enforce one claim per insight at ingest (reject or split bullets containing "and also" style compound claims); add an `interpretation_tested: bool` field for insights that assert why something works, set only after an ablation; untested interpretations keep a reduced confidence multiplier (0.6).
- Teaching protocol to children (`children.py`): every verdict Mandel sends carries `{p, alternatives: [...], evidence_weights: {...}, abstain_if: ...}` rather than a bare recommendation, the distillation-against-the-full-distribution principle; children's scoring then compares their distribution to Mandel's by KL as well as to outcomes.
- Session discipline (MANDEL.md): keep the synthesis-first loading order and the end-of-session write-down; justify it in the document by the context-is-quadratic-and-only-the-last-vector-is-read mechanism, so future sessions understand why the order exists.
- Cheap similarity tooling (`knowledge/`): use normalised compression distance (gzip co-compression, as in the 2002 paper the video cites) as a zero-dependency first-pass measure for clustering child reports and detecting near-duplicate insights before any embedding model is involved; record that it approximates cross-entropy only loosely.
- Metrics to add to the ledger per cycle: `bits_vs_market`, `kl_component`, `permutation_pass_rate`, `ood_calibration_gap`, `selection_temperature`, `adopted_per_cycle`, so the loop's own learning curve (cost per cycle, like a training curve) is inspectable and a flattening slope triggers the step-size rule above.
- Architecture note for the design phase (task #3): the transformer's residual-stream + attention (context-dependent re-reading of each item in light of the others) + MLP (keyed fact lookup) is a useful organising analogy for a knowledge substrate (append-only stream = ledger, attention = cross-linking pass, MLP = insight store), but it is an analogy about information flow, not a mandate to build a neural network; adopt the flow, measure before adopting any structure.
