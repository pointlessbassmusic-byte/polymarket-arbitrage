## What it says (core ideas)

The video's claim, in the creator's words: "My entire life and business now live in one second brain, and Claude Fable understands it better than I do." [skool] It then shows the architecture that makes the claim approximately true: a set of markdown files and folders that the agent can navigate, live connections to changing data, skills and sub-agents that act on both, and automations that run on a schedule.

1. **Two layers, four C's, built in order.** Second Brain = Context + Connections; AI Operating System = Capabilities + Cadence. Context is who you are and what the business is; Connections are live, changing data; Capabilities are skills, sub-agents and pipelines built on the first two; Cadence is capabilities that run without being asked. The order is a dependency chain: "capabilities without context produce hallucination; cadence without capabilities produces nothing." [summ-A, summ-B] Each skipped layer has a named failure: skip Context and agents are noisy; skip Connections and the system goes stale; skip Capabilities and you have only a search tool; skip Cadence and nothing runs while you are away. [wisdom] Chapters: 0:00 full tour; 4:20 Connections (live data via MCP); 8:31 "Other worlds" (consolidating repos); 12:43 Context in action (memory at scale); 16:58 Capabilities (skills and automations); 21:22 day-to-day usage; 25:46 how the second brain compounds; 30:06 wrap-up. [summ-B]

2. **CLAUDE.md is a router, not an instruction list.** The file the agent reads first every session should be a routing tree: explicit paths to the wiki, the hot cache, the master index, the skills folder and the agents folder. "Make it a map, not an essay." [summ-B] The on-screen template has four sections: *Role* (executive assistant / AI operating system for a named user, with the tasks to offload); *Knowledge Base* (paths to wiki, hot cache and master index, "the navigation start point"); *Tools & Integrations* (a `.env` path for keys with a "never log these" note, the skills and agents folders, active MCP connections); *Instructions* (start with the master index for context; use MCP for live data; route automation to skills or agents; "if a file takes over 30 seconds to find, ask the user where it is and update the index"). [summ-B] His later published manual adds: `decisions/log.md` is append-only and the agent should offer to log decisions; nothing is deleted, old material moves to `archives/`; brainstorm captures are read on demand while "confirmed current context belongs in its canonical page." [repo]

3. **Retrieval latency is the health metric of the architecture.** If the agent cannot find a file as fast as you can, the structure is wrong: split files, flatten folders, fix the index. "If your agent takes minutes to find a file you can find in seconds, your architecture needs work." Manual drill-through should feel intuitive and the agent should behave the same way. He calls this a "pulse check" and expects the brain to get messy, so pruning and restructuring are recurring work, as is dropping agents that waste tokens. [summ-A, wisdom]

4. **The knowledge layer is an LLM-maintained wiki with a master index and a hot cache.** Layout named in the video: a wiki path, a hot cache, a master index, and a navigation method. [summ-A, summ-B] The pattern is Karpathy's "LLM Wiki" idea file (4 April 2026), which community members say "clicked" for them once they saw how Herk uses it. [karpathy; Skool thread] In that pattern: raw sources are immutable and the LLM reads but never edits them; the wiki is LLM-owned markdown (summaries, entity and concept pages, comparisons, an overview); a schema file (CLAUDE.md / AGENTS.md) holds the conventions. Three operations: *ingest* (read a source, discuss takeaways, write a summary page, update the index, revise related pages, append to the log; one source touches 10–15 pages), *query* (search the wiki, read, synthesize a cited answer, and file good answers back as new pages so exploration compounds), *lint* (periodic checks for contradictions, stale claims, orphan pages, missing concept pages, absent cross-references, data gaps). `index.md` is a categorized catalog with one line per page, read first on every query; `log.md` is chronological and append-only with greppable prefixes. Karpathy reports index-based navigation works to roughly 100 sources and hundreds of pages without embeddings. "Obsidian is the IDE; the LLM is the programmer; the wiki is the codebase." The wiki is a git repo, so it has version history for free. [karpathy]

5. **Static knowledge and dynamic data are different things and live in different places.** Documents and transcripts go in files; email, ClickUp tasks, QuickBooks P&L and similar are reached live through MCP, APIs or CLIs via the tool harness. [summ-A, summ-B] The video shows the failure mode that motivates the split: a one-shot `/goal` prompt generated a "journey"-style YouTube script from stored context and got his subscriber count wrong, because the number was a static copy. The fix is a live connection, not a fresher copy. [summ-A] His audit later codifies it: live metrics must resolve to live systems or dated exports, and conflicts between a cached figure and a live one are flagged rather than assuming the wiki is right. [repo]

6. **Capabilities: skills, sub-agents, assembly lines, cheap models in parallel.** Skills live in `.claude/skills/` and custom sub-agents in `.claude/agents/` (YAML front matter). Skills can be reusable prompts or multi-stage workflows; complex ones are split into "assembly line" stages with one AI task per stage. Work is delegated to cheaper models (Sonnet or Haiku) in parallel and consolidated by a stronger one. He calls sub-agents and skills the number one productivity feature. [summ-A, summ-B] Examples named: YouTube research, client reporting, content generation, meeting summaries, follow-up drafts. [summ-B, wisdom]

7. **Every skill run is feedback for the skill.** There is "no finished product": each use generates feedback that is folded back into the skill or into CLAUDE.md. Confident-but-wrong output is handled the same way: update the config and the skill, and treat the mistake as system-improvement data. Guardrails that are too sensitive get tuned over time. [summ-A] This is the loop the creator means by "I keep improving the system every day." [skool]

8. **Cadence must earn trust.** Trigger types: manual, event-based (a new email, a customer booking), scheduled (weekly routines). Deployment styles: routines, loops, or deterministic scripts. "More autonomy brings more cost, risk, and maintenance"; automations need visibility, ownership and periodic checks. Build Cadence last and only for workflows that already work manually. [summ-A, repo] Let automations run unattended only when outcomes are low-risk and logs can be audited; start with summaries, reminders and simple routing before automating decisions. [wisdom]

9. **"A prompt is not a permission layer."** Agents should run on keys with the minimum access the task needs (his example: read-only transcript access), because instructions do not constrain behaviour. The cautionary case: an agent sent customer emails with the wrong discount code after interpreting its task "too proactively." [summ-A] The Claude Code docs say the same thing about CLAUDE.md: it is "context, not enforced configuration"; to block an action regardless of what the model decides, use a PreToolUse hook. [docs]

10. **"Other worlds": consolidating repos under the OS project.** Frequently used code projects (a book, a client site, a side project) are moved into an `/other-worlds/` subfolder so one git push syncs everything and the main OS has cross-project context. Trade-off acknowledged: it enlarges what the agent must index and works best when the sub-projects relate to the main work. [summ-A, summ-B]

11. **Context budget as an observable.** His `/context` view starts around 40k tokens, most of it system tools, and large folder projects stay manageable when the architecture is organized. [summ-A] (Mechanics from the docs: all CLAUDE.md files in the directory chain load at launch and are concatenated; `@imports` also load at launch, so they organize but do not save context; target under 200 lines per CLAUDE.md; `.claude/rules/*.md` can be path-scoped so they load only when relevant files are touched; subdirectory CLAUDE.md files load on demand.) [docs]

12. **Demonstrations.** One-shot `/goal` producing a video script from stored context; a one-shot interactive "relationship map" linking concepts, tools and the transcripts or videos they appear in; a heavy task that took about 21 minutes and ran the session down. [summ-A]

13. **Usage tips.** Treat the model as a thought partner and devil's advocate, not an authority. Interview yourself with a "grill me" skill (credited to another creator; the summary's spelling is uncertain) that asks many questions to extract tacit knowledge into files. Verify the work with dynamic workflows and visual or manual testing ("playwright-style clicking"); get to roughly 92% correct fast, then refine. Close other AI tabs and make Claude Code the default interface so context accumulates in one place. [summ-A, summ-B]

14. **The IP is the files, not the model.** "The real IP" is the folders and files, the skills and the routing logic; the system should be portable across providers without a rebuild. He keeps an `AGENTS.md` mirror so Codex can run the same project. [summ-A, levels, repo]

15. **Team and data caveats.** Shared knowledge belongs in central read-only locations; team members should learn the system first; "the biggest risk is shared knowledge going stale." Everything sent through Claude goes to Anthropic, so sensitive client data needs thought. Coding skill is not required on day one if you start from his repo. [summ-A, levels]

16. **Model-launch context (ephemeral).** The video was made during the Claude Fable launch window: free on subscriptions 9–22 June 2026, then usage credits at $10/M input and $50/M output (about 2× Opus), positioned as Mythos-class with more safeguards. He advises experimenting during the window because the model burns limits faster. [summ-A, summ-B]

17. **The five levels (companion video, same creator, 11 days later).** (1) CLAUDE.md router + markdown folders (`context/about-me.md`, `context/stack.md`, `context/decisions.md`, `projects/`); the agent will not search the whole project unprompted, so routing rules must be explicit. (2) LLM wiki + auto memory (`/memory` toggles it; the agent writes `memory.md`; keep `AGENTS.md` for portability). (3) Semantic/vector search (Pinecone, Supabase, Qdrant): good for needle-in-haystack, bad for whole-document questions because it returns chunks; store totals and summaries as plain markdown the agent reads whole. (4) Knowledge graphs (LightRAG, GraphRAG) for relational data; populate them with "grill me" interviews. (5) Full autonomy, which he does not recommend by default. "Pick the lowest level that solves your actual pain"; "work backward from the retrieval question to decide storage"; before blaming the model for poor retrieval, "check whether the information actually made it from your head into the system." He runs his own main project at level 2. [levels]

18. **The audit, as later published (AIS-OS `/audit`).** "A folder, installed skill, API key, or confident claim is not proof of a working system." Each of the four C's is scored out of 25; caps apply for missing or unverified layers; the score measures operational reliability, not usefulness. Five retrieval probes (what the business does and what matters now; where current priority/status lives; where the latest deliverable and next step are; where a past decision is recorded; where a needed external record is and how to access it), each recorded as *found directly*, *found only by fallback search*, or *not found*; "a broad search can recover an answer, but it does not prove the declared route works." A hot cache "earns no credit for existing": it is checked for duplication of canonical pages, a real refresh mechanism, and stale figures presented as current. Connections need successful-read evidence within their refresh interval (default 30 days); a configured key does not prove authentication. Cadence counts only with execution records; a `daily-*` skill name alone does not. Findings get stable IDs tracked across reports in `history.md`; scores are compared only when scope and rubric match; a resolved finding needs fresh evidence; the audit is read-only toward the inspected system. [repo]

19. **Operator rules from the same kit (the "Three Ms").** Mindset: ask how far AI can be leveraged on each task. Method: find the constraint; eliminate / automate / delegate; map the process; choose an autonomy level; tie to a KPI. Machine: simple modular blocks over complex agents, a validation chain, an "intern" rule, a kill switch; "Boring is beautiful. Workflows beat agents." Folder rules: "Don't dump raw email/Slack archives into references/. Store interpreted facts only"; "Flat with good naming beats deep nesting"; "Empty folders are noise"; add a folder only when it is conceptually new, will be touched three or more times a month, and future skills could route there ("Two yeses = add. One yes = wait"); review CLAUDE.md quarterly; archive quarterly. [repo]

20. **Mechanics he relies on, from the docs.** Auto memory lives at `~/.claude/projects/<project>/memory/` with a `MEMORY.md` index (one line per memory) and topic files; only the first 200 lines or 25KB of the index load at session start and anything past that is silently dropped; topic files load on demand; it is machine-local and not shared across machines or cloud environments; subagents do not inherit the main conversation's auto memory; in self-hosted or cloud sessions it is off by default and cannot be turned on from a session another Claude Code session started. Memory files with YAML front matter get a `modified` timestamp on each write. [docs]

## Evidence quality

**Rating: practitioner-anecdotal**, with a promotional component.

- It is one practitioner's account of one setup (n = 1 business), demonstrated rather than measured. No numbers are given for retrieval accuracy, time saved, error rates, or cost per task before and after; the "92% correctness" figure is a feel, not a measurement. The headline claim ("understands it better than I do") is not testable as stated.
- The creator sells a course and runs a paid community, and the video rides a model launch (Fable pricing and availability take up a chapter of the narration). That is a reason to discount enthusiasm, not the architecture; the starter kit itself is free and MIT-licensed, and its audit rubric is unusually self-critical ("never inflate or deliberately depress a score to encourage another run").
- The architectural claims are consistent with two independent sources that do not share his incentives: Karpathy's idea file (the wiki/index/log/lint pattern and the ~100-source scale note) and Anthropic's documentation (CLAUDE.md is context not enforcement; the 200-line / 25KB index limit; auto memory is machine-local). Where the video makes a mechanism claim, those sources back it.
- The safety lessons (least privilege, prompt is not permission, trust earned through logs) are the right lessons, drawn from one anecdote (the discount-code email). Treat the anecdote as illustrative, the lesson as established practice.
- Coverage of the specific video rests on machine summaries; details like the exact chapter titles and the template text come from a single summary site and could be paraphrased.

## What Mandel adopts

1. **Router-first entry: the first file a fresh session reads is a map with explicit paths, not an essay.** Because Mandel's context resets every session and a fresh session's first read decides what it can find; Herk, Karpathy and the docs converge on this and the docs add the reason (adherence drops as the file grows).
2. **A master index with one line per knowledge file, kept under 200 lines / 25KB.** Because that is the hard limit at which Claude Code silently truncates an index, and a limit the harness enforces is a better design constraint than one Mandel promises to respect.
3. **Separate static knowledge from live data, and stamp every stored figure with an as-of date and a refresh interval.** Because the stale-subscriber-count failure is identical to quoting a stale market price or a child's week-old metric as current; a number without an as-of date is not a fact.
4. **Three substrate operations: ingest, query, lint.** Because knowledge should compound (compiled once, cross-referenced, contradictions surfaced) rather than be re-derived from raw sources on every question; `python -m mandel ingest` already exists, query and lint are the missing two.
5. **File good answers back into the substrate.** Because an answer that took effort to synthesize is knowledge; leaving it in a session transcript is the file-drawer problem applied to Mandel itself.
6. **Retrieval probes as a scheduled, evidence-based audit, scored as found-directly / found-by-fallback / not-found.** Because "a folder, installed skill, API key, or confident claim is not proof of a working system," and routing health is measurable with a fixed probe set run from a fresh context.
7. **A hot cache earns no credit for existing: it must have a refresh mechanism and an expiry, and duplication without upkeep is a defect.** Because caches are where stale claims come from; `SYNTHESIS.md` is Mandel's hot cache and must be linted as one.
8. **Append-only decisions log and archive-not-delete.** Because it is the same rule as Mandel's ledger and tombstone principle (p08), independently arrived at by a practitioner for the same reason: you cannot audit what you deleted.
9. **Every use of a procedure produces feedback; feedback becomes a proposal to change the procedure; the change goes through the gate.** Because "no finished product" is right about skills, and Mandel's pre-registration rule (p02) is what keeps continuous tweaking from becoming drift.
10. **Cadence last, and tiered by autonomy: report → remind → route → act; a cadence counts as live only with execution records.** Because trust is earned through logs, and p13 already forbids live-money action without the gate and the user.
11. **"A prompt is not a permission layer": enforce boundaries with hooks and scoped keys, never with instructions alone.** Because CLAUDE.md is context, not configuration, and the discount-code incident is what instruction-only control looks like in production.
12. **Assembly-line decomposition with cheaper models per stage and a stronger model consolidating.** Because p06 (information has a cost) and Mandel's cycle log already measure cost per outcome; the cheapest model that passes the stage's check should run it.
13. **The IP is the files: keep Mandel's knowledge, procedures and routing as plain versioned markdown and code, mirrored for other harnesses (`AGENTS.md`).** Because the children run in sessions Mandel does not control and may run on different harnesses; portability of the substrate is what makes parenting possible.
14. **Structured interviews ("grill me") to pull tacit knowledge out of the user and out of the children.** Because the most common retrieval failure is information that never entered the system, and children's reports will omit what they did not think to say.
15. **Lowest level that solves real pain: no vector store or graph until index-based retrieval demonstrably fails a probe set.** Because Karpathy's index works to ~100 sources and Mandel has about two dozen files; adding retrieval infrastructure before the probes fail is cost without evidence.
16. **Stable finding IDs across audits; compare scores only when scope and rubric match.** Because an audit score is a campaign metric like any other, and comparing across rubric changes is the same error as comparing runs across harness changes (see 04).

## What Mandel holds loosely or rejects

- **"Claude understands my business better than I do" and the "always-aware cofounder" framing.** What the video shows is fast retrieval over files the user wrote plus live reads of systems the user chose. Mandel describes itself as that, per MANDEL.md section 1, and does not borrow the anthropomorphism.
- **The Four C's as a universal build order.** For a predictive substrate, live Connections (market data, children's reports) are prerequisites for most of the Context worth storing, and Capabilities (the gate) exist before Context is complete. Keep the dependency idea (each layer needs the one below) and the "cadence last" rule; drop the fixed ordering.
- **The audit score out of 100 as a measure of value.** The repo itself says it measures operational reliability, not usefulness. Mandel reports probe hit-rates and stale fractions as metrics and never a composite score that invites optimizing the score.
- **"Iterate to ~92% correctness."** A number without a measurement. Reject as a metric; keep the underlying habit (verify by running, not by reading).
- **"Other worlds" repo consolidation.** Moving the children's repositories into Mandel's project would enlarge the index, widen the blast radius of any write, and blur provenance. Mandel reads children through `ChildReport` and writes back through `Guidance`; it does not absorb them.
- **Auto memory as the substrate.** It is machine-local, truncated at 200 lines, not inherited by subagents, off by default in cloud sessions, and cannot be enabled from a session another session spawned. Mandel's memory is the repository; auto memory is a per-session convenience at most.
- **Full autonomy (level 5).** The creator himself does not recommend it. Mandel keeps a human actor in the ledger for ruler changes and live-money changes.
- **Vector search and knowledge graphs now.** Hold until probe failures justify them; and when added, keep aggregates and summaries as whole markdown pages, because chunk retrieval answers the wrong question for totals and comparisons.
- **The model-launch material.** Pricing, availability windows and "experiment during the window" advice are ephemeral and partly promotional; nothing in Mandel's design depends on them.
- **The discount-code anecdote as evidence.** One incident, self-reported; the lesson is adopted on the strength of the docs and general practice, not of the anecdote.
- **Specifics attributed to the narration (chapter titles, template wording, the 40k-token figure, the 21-minute task).** Single-summary provenance; treat as approximately right until a transcript is available.

## Design implications for the RSI predictive substrate

Phrased against the existing `mandel/` modules (`store.py`: `Insight` with kinds principle/fact/heuristic/procedure/metric/question and statuses candidate/validated/retired; `ingest.py`: section bullets → candidate insights with `src:NN`/`adj:AN` provenance; `children.py`: `Child`, `ChildReport`, `Guidance`, `ChildRegistry`; `cycles.py`: `Cycle` with cost and outcome fields; `ledger.py`: hash-chained `Event`; `proposals.py`: `Proposal` lifecycle; `validation/gate.py`; `graph.py`: concept graph over the knowledge files; `MANDEL.md`; `knowledge/README.md`).

**Data structures**
- `knowledge/INDEX.md` (new, the master index): one line per file under `sources/`, `adjacent/`, `campaigns/` and per top-level module doc, in the form `NN | title | evidence_quality | coverage_confidence | last_linted | path`. Hard rule: under 200 lines and 25KB, checked by lint, because that is the limit at which Claude Code truncates an index and Mandel's own index should obey the same bound. `MANDEL.md` and `knowledge/README.md` point to it by path as the first thing to read after the synthesis.
- `knowledge/SYNTHESIS.md` is declared the hot cache: every numeric or state claim in it carries `(as_of: YYYY-MM-DD, source: src:NN | ledger:<event_id> | live:<connector>)`; lint flags any figure older than its source's refresh interval and any figure that duplicates a canonical page without pointing to it. The cache earns no credit for existing.
- `Insight` (extend `store.py`): add `as_of: str | None`, `refresh_interval_days: int | None` (default 30 for kind `fact` and `metric`, None for `principle`), and `source_kind ∈ {static, live, derived}`. `store.query(..., fresh_only=True)` excludes stale facts; stale facts are never emitted in `Guidance`.
- `knowledge/log.md` or ledger kinds `knowledge.ingested`, `knowledge.queried`, `knowledge.linted`, `knowledge.answer_filed` (prefer the ledger, since it is already hash-chained and greppable by kind): each ingest records the file and the insight ids created; each query records the question, the files read, the answer path if filed back; each lint records the finding ids.
- `knowledge/answers/<date>-<slug>.md` (new): synthesized answers filed back into the substrate with the question, the files consulted, the answer, and a confidence; indexed in `INDEX.md` and ingestible like any other file.
- `validation/probes.yaml` (new): a fixed set of 8–12 retrieval questions with the expected target file or insight id, for example "where is the rule for comparing runs across campaigns", "what is the current best Brier score of child X and as of when", "where is the decision that Mandel operates at level 2", "which resource argues against vector search for aggregates", "what does the gate do when the harness hash differs". Each probe has `expected_path`, `max_steps` (tool calls allowed before counting as fallback), and `category ∈ {identity, status, deliverable, decision, external}`, mirroring the five AIS-OS probe categories.
- `knowledge/audits/<date>.md` plus `knowledge/audits/history.md` (new): dated audit reports with findings in sections *confirmed defects*, *verification gaps*, *improvement opportunities*; each finding has a stable id reused across reports; `history.md` is the ledger of finding ids with first-seen, last-seen, resolved-with-evidence.
- `ChildReport` (extend `children.py`): add `as_of`, `source_kind`, and `pointers: list[str]` (paths or URLs where the child's canonical data lives). `Guidance` (extend): add `pointers` as well, so Mandel links to knowledge rather than copying it into the child's context (the `/link` rule: add the route, check it resolves, do not copy the contents).
- Skill feedback files: for every procedure under `mandel/` that children or Mandel run repeatedly (ingest, audit, lint, report intake), a `feedback.jsonl` next to it with `{ts, run_id, outcome ∈ {ok, wrong, slow, blocked}, note}`; a proposal to change the procedure must cite the feedback rows it answers.
- Scheduled procedures registry (`mandel/state/cadence.json`): `{name, trigger ∈ {manual, event, scheduled}, autonomy_tier ∈ {report, remind, route, act}, last_execution_event_id, owner}`; a cadence with no execution event in its interval is reported as *documented but not running* and earns nothing in the audit.

**Loops**
- *Ingest* (exists; extend): after `ingest_knowledge` adds insights, update `INDEX.md` (one line), append a `knowledge.ingested` ledger event, and run the lint checks that touch the new file (orphan, cross-link validity, evidence token present). One source at a time, as Karpathy recommends, so the diff is reviewable.
- *Query* (new, `python -m mandel query "<question>"` or a procedure the children call through Mandel): read `INDEX.md` first, then the named files, answer with citations to `src:NN`/insight ids, and if the answer is non-trivial (more than two sources combined, or any computation) file it under `knowledge/answers/` and ledger it. Never answer a numeric status question from a static page when a live connector or a dated ledger event exists.
- *Lint* (new, `python -m mandel lint`, scheduled weekly and run before any readiness report): orphans (files not in `INDEX.md`, or in the index but missing); broken cross-links (references to `NN` with no file); contradictions (two validated insights on the same concept group in `graph.py` with opposite polarity, surfaced for human decision, not auto-resolved); stale (any `fact`/`metric` past its refresh interval; any `SYNTHESIS.md` figure without an as-of); gaps (concept groups in `graph.py` with mentions in sources but no validated insight); index size (lines, bytes); missing `coverage_confidence` or evidence token. Output: a dated report in `knowledge/audits/` with stable finding ids; `knowledge.linted` event.
- *Retrieval audit* (new, `python -m mandel audit`, scheduled after every change to `MANDEL.md`, `knowledge/README.md` or `INDEX.md`): run each probe in a fresh subagent that receives only the router files, record `found_directly | found_by_fallback | not_found` and steps used, write the report, and update `history.md`. The audit is read-only toward the substrate; its only write is the report.
- *Procedure feedback loop*: every scheduled or child-invoked procedure appends a `feedback.jsonl` row; monthly, rows with `outcome != ok` are clustered into draft proposals (`change_type = procedure_fix`) that cite the rows; the gate evaluates them with the probe set plus the module's tests, and the change is accepted only if probe hit-rate does not fall.
- *Interview loop* (new, "grill me" for the substrate): when a child registers or at each review, Mandel runs a fixed question set (what you optimize, what you measure, what broke last week, what you would not trust, where the data comes from and how fresh it is) and files the answers as a brainstorm capture; confirmed facts are promoted to canonical pages with `as_of`, the capture stays read-on-demand.
- *Cadence promotion*: a procedure may move up one autonomy tier (report → remind → route → act) only after N consecutive logged executions with `outcome = ok` and a human ledger event; `act` on anything touching positions or live money additionally requires the gate (p13). Demotion is automatic on any `wrong` outcome at tier `act`.

**Validation rules**
- A change to any router file (`MANDEL.md`, `knowledge/README.md`, `INDEX.md`) is a `Proposal` whose criterion is `probe_hit_rate_direct >= previous` and `median_probe_steps <= previous`; a regression is rejected even if the prose reads better.
- `INDEX.md` over 200 lines or 25KB fails lint and blocks the readiness report, because content past the limit would be silently unreadable in the harness the children use.
- A `fact` or `metric` insight without `as_of` cannot reach status `validated`. A stale validated fact is downgraded to `candidate` by lint, with a `knowledge.stale` event, until refreshed from its source.
- `Guidance` to a child may contain pointers and validated, fresh insights only; it never contains copied raw content from another child's report (the "store interpreted facts only" rule plus provenance).
- Permission boundaries are enforced in configuration, not prose: PreToolUse hooks deny writes under `validation/` and to live-trading configuration from Mandel and child sessions; market-data keys are read-only where the venue allows; secrets live in `.env` and are never written to the ledger, the knowledge tree or an audit report (the audit prints key names, never values).
- A cadence entry counts as live in reports only if `last_execution_event_id` is within its interval; a `daily-*` name or a cron line is not evidence.
- Audit and lint scores are compared across runs only when `probes.yaml` and the lint rule set are unchanged (their hashes are recorded in the report); a rubric change starts a new baseline, exactly like a campaign tag change in 04.
- No vector index or graph store may be added to the substrate until an audit shows at least two probes `not_found` or `found_by_fallback` for three consecutive runs after routing fixes were attempted; the proposal to add one must cite those reports.

**Metrics**
- Routing: `probe_hit_rate_direct`, `probe_hit_rate_any`, `median_probe_steps`, per category; trend across audits with matching rubric hash.
- Freshness: `stale_fraction` of validated facts; `median_age_days` of figures in `SYNTHESIS.md`; count of live-vs-cache conflicts found by lint.
- Structure: `index_lines`, `index_bytes`, `orphan_count`, `broken_crosslink_count`, `contradiction_count`, `gap_count`; `context_tokens_at_start` as reported by `/context` for a Mandel session (target: flat or falling as the knowledge tree grows).
- Compounding: number of answers filed back per month; fraction of queries answered from the wiki without reopening raw sources; number of insights promoted candidate → validated per cycle (already in `cycles.py` outcomes).
- Procedure health: `feedback_rows`, `fraction_not_ok`, `feedback_to_proposal_conversion`, `procedure_regressions_caught_by_probes`.
- Cadence: procedures per autonomy tier; executions logged vs scheduled; promotions and demotions per period, with the ledger events behind them.
- Cost (p06, `cycles.py`): tokens and dollars per ingest, per query, per lint, per audit; cost per insight validated; share of stage work run on cheaper models.
